# Live trading authorization and dialogs — v3.9.3

Version 3.9.3 removes native browser `alert`, `confirm`, and `prompt` calls from the application frontend. Confirmations and notices render inside the dashboard, use the active light or dark theme, support narrow screens, and preserve the application context while they are open.

Every user-initiated live order placement or cancellation now requires two-factor authentication. The rule is enforced by the server and does not depend on the legacy `require_2fa` preference. It covers Binance.US standard orders, OCO orders, synthetic trailing and ladder/bracket strategies, open-order cancellation, synthetic cancellation, and auto-buy/auto-sell strategy changes. It also covers Webull securities, ETF, option, futures, event-contract, crypto, bracket, trailing, multi-leg, scheduled, and synthetic orders and their cancellation paths.

The placement modal verifies the six-digit TOTP and creates a random session token valid for at most two minutes. The server removes that token as soon as one live trading action presents it, so it cannot authorize a second order. Cancellation dialogs send the entered TOTP directly for that cancellation. A live action is rejected when the code is absent or invalid, when a token is expired, belongs to another user, or has already been consumed, or when the user has not enrolled an authenticator. Paper trading creates and cancels simulated orders without 2FA and cannot reach the live broker path.

Creating a live synthetic strategy authorizes the strategy definition once. Its server-monitored rungs and trailing triggers then execute under that authorization without an interactive prompt because the user is not present when a trigger fires. Cancelling the remaining strategy is a new user action and requires a new code. The cancellation dialog explains that broker-submitted executions are reconciled and completed fills cannot be reversed.

Regression coverage checks mandatory enforcement with the preference disabled, single-use and expiry behavior, live-versus-paper synthetic cancellation, Webull scheduled orders, all supported Webull instrument routes, and the existing synthetic lifecycle. Browser coverage runs the consolidated synthetic table in dark and light themes with Binance.US, Webull, and combined filters, asserts that no native browser dialog opens, and verifies that synthetic cancellation submits the entered code.
